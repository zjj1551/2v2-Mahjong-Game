# mahjong-server 后端文件结构与功能说明

## 1. 后端目录结构（概览）

```text
mahjong-server/
├─ .github/                                # GitHub 配置目录（当前未发现业务文件）
├─ .mvn/
│  └─ wrapper/
│     ├─ maven-wrapper.jar                 # Maven Wrapper 执行核心
│     └─ maven-wrapper.properties          # Maven Wrapper 下载/版本配置
├─ mvnw.cmd                                # Windows 下使用 Maven Wrapper 的启动脚本
├─ pom.xml                                 # Maven 项目配置（依赖、构建、Java 版本）
├─ src/
│  ├─ main/
│  │  ├─ java/com/mahjong/
│  │  │  ├─ MahjongApplication.java
│  │  │  ├─ config/
│  │  │  ├─ controller/
│  │  │  ├─ engine/
│  │  │  ├─ entity/
│  │  │  ├─ model/
│  │  │  ├─ service/
│  │  │  └─ websocket/
│  │  └─ resources/
│  │     ├─ application.yml
│  │     └─ init.sql
│  └─ test/
│     └─ java/com/mahjong/engine/
│        ├─ GameEngineTest.java
│        ├─ ScoreCalculatorTest.java
│        ├─ TileManagerTest.java
│        └─ WinCheckerTest.java
└─ target/                                 # Maven 构建产物目录（编译结果/测试报告）
```

## 2. 根目录文件说明

- `pom.xml`：Spring Boot 3.4.5 的 Maven 配置（已升级修复 CVE 安全漏洞），定义 `spring-boot-starter-web`、`websocket`、`data-jpa`、`mysql-connector-j`、`fastjson2`、`spring-security-crypto`、`lombok`、测试依赖等。
- `mvnw.cmd`：在未全局安装 Maven 的机器上，通过 Wrapper 执行 Maven 命令。
- `maven-wrapper.properties`：指定 Wrapper 使用的 Maven 发行版本与下载源。
- `maven-wrapper.jar`：Wrapper 运行所需二进制。

## 3. 配置与资源文件说明

- `application.yml`：服务端口、数据源、JPA 行为、日志级别等运行配置。
- `init.sql`：数据库初始化脚本，创建 `users`、`game_records`、`friends` 表并插入测试数据。

## 4. 主程序与配置层（config）

- `MahjongApplication.java`：Spring Boot 应用启动入口。
- `CorsConfig.java`：全局 CORS 过滤器配置，允许跨域访问。
- `WebSocketConfig.java`：注册 WebSocket 路由（游戏实时通信入口）。

## 5. 控制器层（controller）

- `UserController.java`：用户相关 HTTP 接口，包括注册、登录、获取用户信息、更新昵称、排行榜、好友添加与查询。
- `RoomController.java`：房间相关 HTTP 接口，包括创建房间、房间列表、房间详情查询（含座位状态、大厅用户列表、准备情况）。

## 6. 业务服务层（service）

- `UserService.java`：用户业务逻辑（注册登录、昵称更新、排行榜、好友关系处理）。
- `RoomService.java`：房间生命周期与会话映射管理（创建、加入、退出、按 session/user 查找）。
- `GameService.java`：对局主流程编排（开局、定缺、出牌、碰杠胡、过、结算广播、记录落库等）。
- `UserRepository.java`：用户数据访问接口（JPA Repository）。
- `FriendRepository.java`：好友关系数据访问接口。
- `GameRecordRepository.java`：对局记录数据访问接口。

## 7. 实体层（entity）

- `UserEntity.java`：用户表实体，包含账号、昵称、积分、胜场、局数、状态等字段。
- `FriendEntity.java`：好友关系实体，记录用户与好友关联及状态。
- `GameRecordEntity.java`：对局记录实体，记录胜负双方、番型、分数、快照、时间等。

## 8. 领域模型层（model）

- `TileType.java`：牌花色/类型枚举与索引映射。
- `Tile.java`：单张牌模型（类型、点数、ID、副本序号等）。
- `Meld.java`：副露（如碰、杠）数据结构。
- `Player.java`：玩家状态模型（手牌、分数、定缺、是否胡牌、会话信息、准备状态等）。
- `GameState.java`：牌局运行时状态（牌墙、当前出牌、轮次等核心状态信息）。
- `Room.java`：房间聚合模型（房间参数、座位玩家表、大厅未就座用户表、状态、当前局信息）。

## 9. 引擎层（engine）

- `TileManager.java`：牌墙初始化、洗牌、发牌、摸牌等牌堆管理。
- `WinChecker.java`：胡牌判定与听牌相关计算。
- `ScoreCalculator.java`：番型与分数计算、输赢结算。
- `GameEngine.java`：对局底层规则执行引擎（推进回合、规则校验、状态变更）。

## 10. WebSocket 通信层（websocket）

- `MessageType.java`：WebSocket 消息类型枚举（含选座/准备/离开/开始等大厅消息）。
- `GameMessage.java`：统一消息载荷对象（类型、数据、错误码等）。
- `GameWebSocketHandler.java`：WebSocket 连接管理与消息分发，处理大厅选座/准备/离开及游戏对战全流程。

## 11. 测试代码（src/test）

- `TileManagerTest.java`：验证牌墙与发牌/摸牌行为。
- `WinCheckerTest.java`：验证胡牌判定、七对、清一色、定缺等规则。
- `ScoreCalculatorTest.java`：验证番数计算与结算逻辑。
- `GameEngineTest.java`：验证对局流程推进（开局、出牌、摸牌、回合切换等）。

## 12. 构建产物目录说明

- `classes/`：主代码编译后的 `.class` 文件。
- `test-classes/`：测试代码编译后的 `.class` 文件。
- `surefire-reports/`：单元测试报告。
- `generated-sources/`、`generated-test-sources/`、`maven-status/`：Maven 构建过程生成的中间文件。

> 说明：`target/` 下属于可再生文件（构建产物），通常不作为核心业务代码阅读重点。

### 13.2 待完成功能 ❌

| # | 功能 | 优先级 | 说明 |
|---|------|-------|------|
| 1 | **出牌倒计时与超时自动出牌** | 🔴 高 | `S_COUNTDOWN` 消息类型已预留，但 `GameService` 中没有定时器逻辑。需要 `ScheduledExecutorService` 在每次轮到玩家操作时启动倒计时（建议 15-20 秒），超时后自动出手牌中的一张（如最后一张摸到的牌）。涉及文件：`GameService`、`GameWebSocketHandler`。 |
| 2 | **庄家轮转规则** | 🔴 高 | 当前庄家按 `(round-1) % 4` 简单轮转，但四川麻将规则应为：胡牌者或上局庄家（若荒庄）连庄；血战到底中以最后胡牌者决定下局庄家。需修改 `GameService.handleRoundEnd` 及 `GameEngine`。 |
| 3 | **番型描述写入对局记录** | 🟡 中 | `GameRecordEntity.winType` 字段已存在但 `GameService.saveGameRecord` 未填充。需调用 `ScoreCalculator` 返回的番型字符串赋值。 |
| 4 | **获取历史对局记录 REST 接口** | 🟡 中 | `GameRecordRepository` 已有按房间/按玩家查询方法，但未暴露 HTTP 接口。需在 `RoomController` 或新建 `GameController` 中添加 `GET /api/room/{roomId}/records` 及 `GET /api/user/{userId}/records`。 |
| 5 | **听牌提示推送** | 🟡 中 | `WinChecker.getTingTiles` 已实现，但每次摸牌后 `GameService.doDrawTile` 未计算并推送听牌列表。需在 `S_DRAW` 消息的 `data` 中附加 `tingTiles` 字段。 |
| 6 | **好友申请双向确认机制** | 🟡 中 | `FriendEntity.status`（0=申请中，1=已添加）字段已存在，但 `UserService.addFriend` 直接以 status=1 入库，跳过了申请→确认流程。需增加 `POST /api/user/friend/accept/{requestId}` 和 `POST /api/user/friend/reject/{requestId}` 接口。 |
| 7 | **房间内好友邀请** | 🟡 中 | 开题报告中提到房间邀请机制（通过好友关系），目前完全缺失。可通过 WebSocket 实现或 REST 接口推送邀请通知。 |
| 8 | **观战模式（只读旁观）** | 🟡 中 | 开题报告扩展功能。可复用现有 WebSocket 基础设施，允许非座位用户进入大厅后收到牌局广播（需过滤私密手牌消息）。`Room.lobbyUsers` 大厅结构已具备承载观战者的基础。 |

### 13.3 扩展功能（开题报告标注为"视进度推进"，当前未实现 ⬜）

| # | 功能 | 说明 |
|---|------|------|
| 9 | **赛事管理模块** | 支持创建赛事、报名、积分制/瑞士制/单败淘汰赛程自动编排。需新建 `Tournament` 实体与相关 Service/Controller。 |
| 10 | **自定义游戏规则** | 在建房时允许设置自定义番型分值（如杠牌底分、某番型倍率）。需扩展 `Room` 模型的配置字段，并将参数传入 `ScoreCalculator`。 |
| 11 | **Redis 实时状态缓存** | 将 `Room`、`GameState` 等内存对象序列化存入 Redis，支持多实例部署和服务重启后状态恢复，同时可用于赛事回放数据记录。 |
| 12 | **赛事回放** | 将每局每步操作（出牌/碰/杠/胡）以时间戳记录到 Redis/DB，提供回放接口。需新增 `ReplayRecord` 数据结构和回放控制器。 |
| 13 | **多人实时观战** | 在观战基础上，需要向观战者推送脱敏后的完整牌局状态（所有人手牌）。需要扩展 `MessageSender.broadcast` 为「观战版广播」。 |
| 14 | **AI 托管（超时自动接管）** | 结合倒计时（功能 #1），在玩家超时或断线时，由 AI 策略模块接管出牌决策。简单版可实现「出听牌时的最优牌」；完整版引入向听数最小化策略。 |
| 15 | **人机模式（对战 AI）** | 建房时允许添加 AI 玩家占座，AI 玩家无真实 WebSocket 连接，由后端线程驱动操作。需新建 `AiPlayer` 逻辑模块。 |
| 16 | **防作弊系统（MDP 预警）** | 基于马尔可夫决策过程，在后台计算当前局面的理论最优出牌策略，与玩家实际操作比对，连续异常操作达到阈值后触发预警记录。 |
